## Registered Specialist Subagents

| typescript-game-logic | Delegate for any work in the pure-TypeScript simulation modules under src/ — game.ts, physics.ts, obstacles.ts, collision.ts, score.ts, rng.ts, events.ts, input.ts, sprites.ts, tuning.ts, store.ts, assert.ts, types.ts. | canvas-browser-shell | Delegate for anything that touches the browser shell — src/main.ts (bootstrap, requestAnimationFrame loop, canvas sizing, window.__dino hook, localStorage adapter), src/render.ts (Canvas 2D drawing, layer system, setCamera, HUD painting) and src/input-dom.ts (keydown/keyup/blur/visibilitychange adapter) — plus index.html and src/style.css. Not for pure simulation modules (that is typescript-game-logic). | typescript-development, verify-ui |

| playwright-tester | Delegate for the single Playwright smoke test in e2e/smoke.spec.ts and its playwright.config.ts. Maps each acceptance criterion in functional-spec.md to the tests that already cover it, writes one acceptance-level test for each criterion that has none, proves only those new tests with RED validation, runs the suite once, and reports a criterion-by-criterion coverage table. Records uncovered criteria under "## Open Questions" in tasks.md. Not a per-task test writer: implementers prove their own tests. | — |

## Gaps

- ESLint `no-restricted-globals` / `no-restricted-properties` / `no-restricted-syntax` configuration: no registry skill carries the DOM-and-determinism allow-list pattern — `vite-build-tooling` falls back to general TypeScript knowledge → prepare a project-local skill under `.claude/skills/` if the ESLint rules churn.
- GitHub Pages deploy (`base` from `BASE_PATH`, optional job): no Pages-specific skill in the registry → `github-actions-ci` uses general knowledge; add a project note if a public demo is wired up.
- No format-on-edit / pre-commit lint / test-on-stop hooks found in the registry → `npm run check` still enforces the same gates at CI time; add a local `.husky/` or `settings.json` hook if interactive feedback becomes a pain point.
